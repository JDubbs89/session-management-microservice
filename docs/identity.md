# Accounts, tokens, and request limits

`POST /users/register` requires only `username` and `password`. The API generates a UUID `user_id` and a stable UUID `subject`. The optional legacy `user_id` input is accepted but ignored: use the returned ID. Steam is optional. Supplied Steam IDs are self-asserted compatibility data, never proof of Steam ownership. External identity records carry `verified=false`; linking or authenticating verified external providers is deferred until provider verification is implemented.

Migration 006 adds a neutral subject to every existing account and copies nonempty Steam identifiers into `account_external_identities`. Existing user IDs and session host references remain intact, so old references continue to work. New JWTs use the neutral subject with `identity=account`; unexpired legacy username-subject JWTs still undergo online-state, role, and persistent token-version checks. Legacy accounts form one compatibility namespace; tenant-specific service players use the scoped service API and its explicit delegation authorization.

Logout increments the PostgreSQL token version and marks the account offline in the same transaction. Later login does not reset the version. All earlier tokens remain revoked across API/game/database restarts. Tokens expire after `ACCESS_TOKEN_EXPIRE_MINUTES` (30 by default). There is no refresh token or automatic extension: expiry requires password authentication. Multiple tokens issued before logout share a version; logout invalidates all of them. Account deletion removes the account, making all its tokens unusable.

Authenticated requests receive an independent principal budget (120/minute) and IP ceiling (1200/minute). Route-specific legacy limits also use the verified player when available. The shared IP ceiling intentionally accommodates several players behind a game server. Authentication failure never earns an attacker a player budget based on unverified JWT claims. Service credentials receive a stable service budget across credential rotation. Exhaustion returns HTTP 429 with `Retry-After`.

`RATE_LIMIT_STORAGE=postgresql` shares principal/IP counters across workers and restarts, using atomic upserts in separate committed transactions. Counter storage failure fails closed with HTTP 503. Expired keys are cleaned incrementally on requests. Production requires PostgreSQL storage. Development/test defaults to `memory`, suitable for one process; select PostgreSQL to exercise distributed behavior. Local legacy route decorators provide additional process-local burst limits, while the shared principal/IP budget applies across workers.

Forwarded headers are not read by the limiter. Run Uvicorn with `--no-proxy-headers` by default. If deployment requires original client IPs, configure Uvicorn's trusted proxy allowlist to the exact ingress addresses and prevent direct access around ingress; never trust `*`. Otherwise budgets use the socket peer (typically the game server), with separate verified player/service budgets.
